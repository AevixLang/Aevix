# Aevix

🌍 Языки: [English (оригинал)](../../README.md) · **Русский**

**Aevix** — высокопроизводительный язык системного программирования, созданный для обеспечения скорости уровня C/C++ с более строгими гарантиями безопасности.

## Философия

Aevix стремится выйти за рамки существующих языков, объединяя:

- **Максимальную производительность** — компиляция заранее (AOT) через LLVM, абстракции нулевой стоимости.
- **Безопасность памяти** — без сборщика мусора и без сложностей механизма проверки заимствований.
- **Контроль разработчика** — явное управление памятью, когда это необходимо, и безопасность по умолчанию.

## Ключевые возможности

### Реализовано (v0.1)

- **Статическая система типов** — `int`, `float`, `bool`, `string`, типы фиксированной ширины (`i8`–`u64`, `f32`/`f64`), структуры (`struct`), перечисления (`enum`).
- **Память на основе арен (эпохи)** — откат за O(1), без сборщика мусора и без проверки заимствований.
- **Параметры по ссылке** — `ref` с проверками псевдонимов и предотвращением утечек за пределы области.
- **Массивы и срезы** — массивы фиксированного размера (передаются по значению) и открытые срезы (выделяются в арене).
- **Встроенные строковые функции** — `split`, `join`, `trim`, `upper`, `lower`, `contains`, `replace`, `startswith`, `endswith`, `char_at`.
- **Горячие регионы** — блок `hot { }` помечает критический путь: атрибут `hot` для функции, метаданные векторизации и развёртывания циклов, выравнивание локальных переменных по кэш-линии, предвыборка выделений памяти (`epoch` внутри запрещён).
- **Многофайловые импорты** — с обнаружением циклов, псевдонимами импортов / пространствами имён (`import "mod" as mod;`) и поддержкой пакетов.
- **Менеджер пакетов** — `aevix-pm` управляет файлами `aevix.toml` / `aevix.lock`; компилятор разрешает импорты вида `пакет:модуль` по файлу `aevix.lock` (локальные зависимости по путям).
- **Фронтенд на C++** — в 20 раз быстрее устаревшего фронтенда на Python.

### Планы развития

- **Самооптимизирующаяся семантика (SOS)** — генерация SIMD-инструкций и продвижение данных на стек, управляемые компилятором.
- **Контекстуальный полиморфизм** — генерация кода функции подстраивается под контекст места вызова.
- **Доказуемая безопасность** — проверка инвариантов во время компиляции для устранения проверок во время выполнения.

## Архитектура проекта

```text
aevix/
├── frontend/
│   ├── cpp/             # лексер и парсер на C++ → типизированное JSON-дерево AST (основной)
│   │   ├── src/         # lexer.hpp, parser.hpp, ast.hpp, importer.hpp, json_out.hpp
│   │   └── build/       # исполняемый файл aevix-frontend
│   ├── src/             # фронтенд на Python (устаревший запасной вариант)
│   │   └── parser.py, transformer.py, ast.py, importer.py, main.py
│   └── grammar/
│       └── aevix.lark   # грамматика Lark EBNF (эталон)
├── backend/
│   ├── sema/
│   │   └── sema.cpp     # статический анализ (типы, области видимости, безопасность эпох)
│   ├── src/
│   │   ├── codegen.cpp  # генерация LLVM IR
│   │   ├── json_reader.cpp  # десериализация AST
│   │   └── aevix_runtime.c  # аренный аллокатор, ввод-вывод, встроенные функции
│   └── build/           # aevix-backend, aevix-sema, runtime.o
├── tools/
│   └── cmd/aevix/main.go   # консольная утилита на Go, управляющая конвейером
└── examples/            # 29 примеров программ (.aev)
```

## Конвейер компилятора

```text
main.aev ──► [фронтенд: C++ (или запасной Python)] ──► ast.json (схема v5)
     ──► [семантика: C++] ──► статический анализ (типы, области видимости, безопасность эпох)
     ──► [бэкенд: C++ + LLVM] ──► output.ll (LLVM IR)
     ──► [opt -O2] ──► output.opt.ll (оптимизированный IR с учётом метаданных `hot`)
     ──► [llc] ──► output.o
     ──► [clang + runtime.o] ──► program (исполняемый файл)
```

## Начало работы

### Требования

- Компилятор C++ с поддержкой стандарта C++17 (`clang++` или `g++`)
- **LLVM** (должен быть доступен в системной переменной `PATH`)
- Go 1.25+
- Python 3.8+ (только для запасного фронтенда на Python)

### Установка

Вместо ручной настройки используйте скрипт начальной настройки. Он подготовит виртуальное окружение Python, соберёт компоненты C++ и скомпилирует консольную утилиту на Go.

```bash
python bootstrap.py
```

### Использование компилятора

После настройки для сборки и запуска программ используется команда `aevix`:

```bash
# Собрать программу
./aevix build examples/test.aev

# Собрать и запустить программу
./aevix run examples/test.aev

# Собрать, запустить и передать аргументы программы (argc()/arg(i))
./aevix run examples/test.aev alpha beta

# Запустить полный набор интеграционных тестов
./aevix selftest

# Удалить артефакты сборки
./aevix clean
```
*В Windows используйте `aevix.exe` вместо `./aevix`.*

### Глобальная установка

Скрипт настройки также создаёт символическую ссылку на утилиту в `~/.local/bin`, поэтому после запуска `python bootstrap.py` (или `source activate.sh`) команда `aevix` работает из **любой** директории — утилита находит репозиторий компилятора по собственному пути, а относительные пути `.aev` и файловый ввод-вывод программы разрешаются относительно текущего рабочего каталога:

```bash
aevix run ~/somewhere/else/prog.aev   # работает из любой директории
```

### Пример

```aev
let x = 10;
let y = 20;
let z = x + y;
let w = z * 2;
let n = -w;

hot {
    let t = n + 1;
    print t;
}
```

Аргументы командной строки, стандартный ввод и файловый ввод-вывод работают из коробки:

```aev
hot {
    let who = input();                       // строка из стандартного ввода
    if (len(who) == 0) { who = "world"; }    // "" в конце файла
    let msg = "hello, " + who + "!";
    write("out.txt", msg);
    print read("out.txt");
}
```

## Статус

🚧 Альфа-версия — проект активно развивается. Пока не готов к промышленному использованию. Конвейер фронтенда и бэкенда сейчас работает от начала до конца.

### Известные ограничения

- Объявления `func` разрешены только на верхнем уровне файла.
- `import` допустим только на верхнем уровне. Без `as` импортируемые объявления объединяются в глобальную область; `import "mod" as mod;` изолирует их за псевдонимом (`mod.fn()`, `mod.Type`, `mod.Color.red`).
- Импорты пакетов (`имя:модуль`) разрешаются через `aevix.lock` проекта, которым управляет `aevix-pm`. Локальные зависимости по путям поддерживаются; получение пакетов по версиям из реестра появится позже.
- Арена растёт по мере необходимости, но отдельные выделения никогда не освобождаются; блоки эпох откатывают указатель выделения.
- Блок `hot` ускоряет циклы (слоты выровнены по кэш-линии, метаданные векторизации и развёртывания используются этапом `opt -O2`, предвыборка выделений памяти), но распределение регистров внутри оставлено оптимизатору LLVM.
- Механизмов SOS (самооптимизирующейся семантики) и контекстуального полиморфизма пока нет.
