# Синтаксис Aevix

Этот документ содержит полную спецификацию языка Aevix (v0.3.9). Это русский перевод оригинального [Syntax.md](../../Syntax.md).

## ⚡ Быстрый старт

```aev
func calculate_sum(limit: int) : int {
    let total = 0;
    for (let i = 0; i < limit; i += 1) {
        total += i;
    }
    return total;
}

let result = calculate_sum(100);
print result;
```

---

## 1. Система типов

Aevix — статически типизированный язык. Типы можно объявлять явно или выводить автоматически.

| Тип | Описание | Соответствие в LLVM |
| :--- | :--- | :--- |
| `int` | 32-битное знаковое целое | `i32` |
| `float` | Вещественное число двойной точности (псевдоним `f64`) | `double` |
| `bool` | Логическое значение (`true` / `false`) | `i1` |
| `string` | Срез строки UTF-8 (`{ i8*, i32 }`) | `{ i8*, i32 }` |
| `i8`, `i16`, `i32`, `i64` | Знаковые целые фиксированной ширины | `i8`, `i16`, `i32`, `i64` |
| `u8`, `u16`, `u32`, `u64` | Беззнаковые целые фиксированной ширины | `i8`, `i16`, `i32`, `i64` |
| `f32` | 32-битное вещественное число | `float` |
| `f64` | 64-битное вещественное число | `double` |

Типы фиксированной ширины автоматически повышаются до `int`/`float` в арифметике. Присвоение более широкого значения более узкой цели — ошибка компиляции, если значение не помещается.

## 2. Переменные и присваивания

### Объявления

Используйте ключевое слово `let`. Поддерживается вывод типа.

```aev
let x: int = 10;      // явно
let y = 20.5;         // выведено как float
let active = true;    // выведено как bool
```

### Обновления

Существующие переменные обновляются простым присваиванием:

```aev
x = 15;
```

Составное присваивание поддерживается для арифметических операторов над числовыми целями (переменные, элементы массивов, поля структур):

```aev
x += 5;      // x = x + 5
x -= 3;      // x = x - 3
x *= 4;      // x = x * 4
x /= 2;      // x = x / 2
```

Значение `int` автоматически повышается до `float`, когда цель имеет тип `float` (`f += 2`); присвоение `float` в цель типа `int` — ошибка. Составное присваивание для строк, логических значений и открытых массивов (срезов) запрещено.

## 3. Выражения

### Операторы

| Категория | Операторы | Описание |
| :--- | :--- | :--- |
| **Арифметика** | `+`, `-`, `*`, `/`, `%` | Базовая математика; `%` — остаток (int или float) |
| **Сравнение** | `==`, `!=`, `<`, `>`, `<=`, `>=` | Логические результаты |
| **Логика** | `&&`, `\|\|`, `!` | Булева алгебра |
| **Унарные** | `-`, `!` | Отрицание / инверсия |

### Приоритет операторов

Операторы упорядочены от высшего приоритета к низшему:

1. `()` — скобки
2. `!`, `-` — унарные операторы
3. `*`, `/`, `%` — умножение, деление и остаток
4. `+`, `-` — сложение и вычитание
5. `==`, `!=`, `<`, `>`, `<=`, `>=` — сравнения
6. `&&` — логическое И
7. `||` — логическое ИЛИ

## 4. Управление потоком

### Условный оператор (`if`)

```aev
if (condition) {
    // блок «то»
} else {
    // блок «иначе» (необязателен)
}
```

### Сопоставление с образцом (`match`)

```aev
match (expr) {
    case value: { /* тело */ }
    case value: { /* тело */ }
    default:    { /* тело */ }
}
```

`match` сравнивает исследуемое значение по равенству и выполняет тело первой совпавшей ветки; `default` необязателен. Каждая ветка должна заключать своё тело в фигурные скобки. Значениями могут быть литералы, переменные или полные имена вариантов перечислений (`Color.red`).

У `match` есть также форма выражения, возвращающая значение:

```aev
let y = match (x) {
    case 1 => 10,
    case 2 => 20,
    default => 30
};
```

Каждая ветка использует `=>` и возвращает одно выражение; все ветки должны иметь одинаковый тип. `default` обязателен, если исследуемое значение не является перечислением, и может быть опущен, когда покрыты все варианты перечисления.

### Цикл `while`

```aev
while (condition) {
    // тело
}
```

### Итерация (`for`)

Цикл в стиле C: `for (init; condition; step) { body }`

```aev
for (let i = 0; i < 10; i += 1) {
    print i;
}
```

Любую из частей можно опустить (`for (;;)`, `for (; i < 5; i += 1)` и т.д.), а шаг может использовать составное присваивание.

### Итерация (`for-in`)

Обход элементов массива: `for var in array { body }`

```aev
let nums = [10, 20, 30];
for x in nums {
    print x;
}
```

### `break` / `continue`

`break` прерывает внутренний цикл; `continue` переходит к следующей итерации (к шагу в `for`, к проверке условия в `while`/`for-in`). Оба допустимы только внутри цикла — в любом другом месте это ошибка компиляции.

```aev
for (let i = 0; i < 10; i += 1) {
    if (i == 3) { continue; }     // пропустить 3
    if (i == 6) { break; }        // остановиться на 6
    print i;
}
```

## 5. Функции

Функции определяются с помощью ключевого слова `func`. Тип возвращаемого значения необязателен (по умолчанию `void`).

Вложенные объявления `func` **навсегда запрещены** — они могут появляться только на верхнем уровне файла, и компилятор сообщает: `function declarations are only allowed at the top level`.

```aev
func power(base: float, exp: float) : float {
    return base * exp;
}
```

### Параметры по ссылке

Добавьте префикс `ref` к параметру, чтобы передать его по ссылке (для чтения и записи). Аргумент должен быть lvalue (переменная или выражение, которому можно присвоить значение); временные значения, варианты перечислений и два `ref`-параметра, привязанные к одной переменной, — ошибки компиляции. `ref` пишется только в объявлении параметра — в месте вызова передаётся обычный аргумент.

```aev
func swap(a: ref int, b: ref int) {
    let tmp = a;
    a = b;
    b = tmp;
}

let x = 1;
let y = 2;
swap(x, y);
print x;  // 2
print y;  // 1
```

## 6. Модули и импорты

Исходный файл может подключать объявления (`func` / `struct`) из других файлов:

```aev
import "utils.aev";            // путь относительно импортирующего файла
import "geometry/circle";      // ".aev" дописывается, если расширение отсутствует
import "submit:io";            // пакет "submit", модуль "io" (через aevix.lock)
import "utils.aev" as u;       // поместить модуль за псевдонимом
```

Правила:

- Импорты разрешены только на верхнем уровне файла.
- Порядок разрешения пути: относительно импортирующего файла → каталог `lib/` проекта → каталоги из `$AEVIX_PATH`.
- Спецификация с `:` — это импорт пакета (`пакет:модуль`); компилятор находит пакет через `aevix.lock` проекта (этот файл создаёт менеджер пакетов).
- `std:` — стандартная библиотека, поставляемая с инструментарием. Она обходит `aevix.lock` и разрешается через каталог `stdlib/` компилятора (или `$AEVIX_STDLIB`). `import "std:"` загружает все модули; `import "std:text"` — только один. См. [Стандартная библиотека](#14-стандартная-библиотека).
- Без `as` импортируемые **объявления** объединяются в одну плоскую программу. Верхнеуровневые операторы модуля (его побочные эффекты) отбрасываются.
- С `as псевдоним` каждое экспортируемое объявление оказывается за этим псевдонимом: вызывать как `alias.fn(...)`, именовать типы как `alias.Point`, создавать их как `alias.Point { ... }`, получать варианты перечислений как `alias.Color.red`. Поэтому два модуля могут экспортировать одно и то же имя под разными псевдонимами. Модуль можно импортировать под более чем одним псевдонимом, а модуль без `as` по-прежнему объединяется плоско.
- Файл, импортированный более одного раза, включается только один раз (дедупликация по реальному пути).
- Циклические импорты — ошибка.
- Имя, определённое в двух разных файлах, — конфликт (ошибка), если только оба модуля не импортированы под псевдонимами, которые их разделяют.
- `as` и `import` — зарезервированные слова (их нельзя использовать как идентификаторы).

### Менеджер пакетов (`aevix-pm`)

Компилятор только *читает* граф пакетов; инструмент `aevix-pm` *записывает* его. `aevix-pm` поддерживает два файла в корне проекта:

- `aevix.toml` — манифест: имя вашего пакета, версия и объявленные зависимости (намерение, редактируемое человеком).
- `aevix.lock` — разрешённый и закреплённый граф (JSON): точная версия и путь каждой зависимости. Именно его использует компилятор.

```bash
aevix-pm init myapp                          # создать aevix.toml + aevix.lock
aevix-pm add calc --path ../calc             # локальная зависимость по пути
aevix-pm add remote --git https://host/repo --version "^1.2"
aevix-pm remove calc                         # удалить её и пересобрать lock-файл
aevix-pm list                                # показать объявленные зависимости
aevix-pm install                             # материализовать git-зависимости из lock
aevix-pm update [name]                       # новейший тег в объявленном диапазоне
aevix-pm vendor                              # скопировать зависимости в lib/vendor/
aevix-pm tree                                # показать разрешённый граф
aevix-pm why calc                            # объяснить, почему пакет присутствует
```

`aevix-pm add` записывает зависимость в `aevix.toml` и заново создаёт `aevix.lock` детерминированно, поэтому различия остаются минимальными. Пакет — это каталог с файлами `.aev`; `import "calc:"` (пустой модуль) загружает точку входа `lib.aev`, а `import "calc:num"` загружает `num.aev` внутри него.

Поддерживаются два источника зависимостей:

- **`path`** — локальный каталог относительно корня проекта. Удобно для монорепозиториев; копия не создаётся.
- **`git`** — URL для клонирования. `add --git` выбирает новейший semver-тег, удовлетворяющий `--version` (или явному `--rev`), материализует его в `lib/<имя>/` и закрепляет точный SHA коммита в `aevix.lock`. `install` воспроизводит это закреплённое дерево на другой машине без повторного разрешения версий. `vendor` копирует все зависимости в `lib/vendor/<имя>/` для полностью офлайн-сборки.

Центрального HTTP-реестра в линии 0.3 **нет**; поддерживаемый удалённый источник версий — git-теги. Публикация и загрузка из реестра запланированы на 0.4.

## 7. Массивы и срезы

Массивы фиксированного размера копируются по значению; открытые массивы (`int[]`) — это срезы `{ data*, len }`, выделяемые в арене.

```aev
let a: int[3] = [1, 2, 3];       // массив фиксированного размера, копируется по значению
print a[1];                      // 2

let b: int[] = [4, 5, 6];        // открытый массив (срез) — копируется в арену
print len(b);                    // 3
b[0] = 9;                        // изменение видно через срез
```

`for-in` обходит любой массив или срез:

```aev
let nums: int[] = [10, 20, 30];
for x in nums { print x; }
```

### `new` — выделение в арене

```aev
let n = 5;
let buf = new int[n];            // размер известен во время выполнения, память обнулена
buf[0] = 42;
let pts = new Point[2];          // массив структур, память обнулена
```

Выход за границы массива прерывает программу с ошибкой границ во время выполнения.

## 8. Строки

Строки — это срезы `i8`, поэтому они являются значениями: их можно сравнивать, конкатенировать и индексировать.

```aev
let s: string = "hello";
print s;                 // hello  (без кавычек)
print len(s);            // 5
print s[0];              // h  (символ; пригоден как int: s[0] + 1)
let t = s + " world";    // конкатенация (выделяется в арене)
if (s == "hello") { ... }
if (s != "hello") { ... }
```

Строки работают как параметры и возвращаемые значения функций, а также как поля структур. Массивы строк поддерживаются во всех тех же формах, что и `int`: открытые срезы `string[]`, массивы фиксированного размера `string[N]`, `new string[n]`, поля структур и параметры:

```aev
let parts = split("a,b,c", ",");      // -> срез string[] (выделен в арене)
print parts;                          // ["a", "b", "c"]
print parts[1];                       // b
parts[2] = "z";                       // изменяемые элементы
print len(parts);                     // 3
for w in parts { print w; }           // обход
let words: string[2] = ["x", "y"];    // массив фиксированного размера
let fresh = new string[2];            // обнулён: ["", ""]
```

`split(s, sep)` разбивает `s` по каждому вхождению `sep` и возвращает срез `string[]`. Пустые фрагменты сохраняются (`"a,,b"` с разделителем `","` даёт `["a", "", "b"]`); пустой разделитель возвращает `[s]` без изменений.

Строковые литералы поддерживают управляющие последовательности `\n`, `\t`, `\r`, `\\` и `\"`; любая другая последовательность с обратной косой чертой сохраняется дословно:

```aev
let msg = "line 1\nline 2\t-tabbed";
```

### Интерполированные строки (f-строки)

Символ `f` непосредственно перед открывающей кавычкой помечает интерполированную строку. `{выражение}` вставляет значение любого выражения; `{{` и `}}` выводят литеральные фигурные скобки. Интерполяция раскрывается в конкатенацию и вызовы `to_str`, поэтому строки проходят без изменений, а числа форматируются так же, как в `to_str`/`print`:

```aev
let name = "Aevix";
let n = 3;
print f"hello, {name}! n={n}, n+1={n + 1}";   // hello, Aevix! n=3, n+1=4
print f"{{literal braces}}";                  // {literal braces}
```

Одиночный `f` остаётся обычным идентификатором. Пустые `{}` и незакрытая `{` — ошибки разбора. И фронтенд на C++, и запасной фронтенд на Python раскрывают f-строку в одну и ту же форму `+`/`to_str`.

`to_int`/`to_float` разбирают ведущее число строки; `to_str` форматирует значения int/float обратно в строки, поэтому числа и текст свободно сочетаются:

## 9. Структуры

```aev
struct Point { x: int, y: int }
struct Bag { items: int[], tag: string }

let p = Point { 1, 2 };                    // позиционный литерал
print p.x + p.y;                           // 3

let q = Point { y: 2, x: 1 };              // именованные поля, любой порядок
print q;                                   // {1, 2}

let b = Bag { new int[3], "box" };         // поля с открытыми массивами допустимы
b.items[1] = 55;
print b;                                   // {[0, 55, 0], box}

let c = Bag { tag: "bag", items: new int[3] };
```

Поля структур доступны через `.`; работают цепочки доступа к полям и массивы структур.

Литералы структур могут быть полностью позиционными или полностью именованными — два стиля нельзя смешивать внутри одного литерала. Именованные поля могут идти в любом порядке, но каждое поле должно быть задано ровно один раз; значений по умолчанию нет. Неизвестное, продублированное или пропущенное имя — ошибка компиляции.

## 10. Перечисления (`enum`)

Перечисления определяют набор именованных целочисленных констант. Вариантам присваиваются индексы в порядке объявления, начиная с 0.

```aev
enum Color { red, green, blue }
enum Direction { north, south, east, west }

let c = Color.red;
print c;                    // 0
print c == Color.green;     // false

if (c == Color.red) {
    print "facing red";
}
```

Значения перечислений внутри представлены как `i32`. Их можно сравнивать, печатать (печатается имя варианта) и использовать в условиях `if`. Присваивать значение варианту перечисления или передавать его как `ref`-параметр — ошибка компиляции.

## 11. Эпохи (откат арены)

`epoch { ... }` сохраняет позицию арены на входе и восстанавливает её на выходе, логически освобождая всё, что было выделено внутри. Переменные, определённые до эпохи, сохраняются; срезы не могут выходить за её пределы.

```aev
let keep = new int[2];
epoch {
    let tmp = new int[1000];   // отбрасывается при выходе из эпохи
}
print len(keep);               // по-прежнему 2
```

## 12. Стандартный ввод-вывод и встроенные функции

Вывод обрабатывается оператором `print` (поддерживаются int, float, bool, строки, массивы/срезы, структуры):

```aev
print "System status: OK";
print 404;
```

`print` принимает несколько выражений, разделённых запятыми, в одной строке; значения разделяются пробелом, а перевод строки выводится один раз в конце:

```aev
print 1, "two", 3.5;         // 1 two 3.500000
```

Логические значения печатаются как слова `true` / `false` (в том числе внутри массивов и структур). Массивы фиксированного размера и открытые массивы (срезы) печатаются в одной и той же форме со скобками — как для скаляров, так и для строк и структур: `[{1, 2}, {3, 4}]`.

### Встроенные функции

| Функция | Сигнатура | Описание |
| :--- | :--- | :--- |
| `len(x)` | `len(array or string) -> int` | Длина массива, среза или строки |
| `argc()` | `argc() -> int` | Количество аргументов командной строки (после имени программы) |
| `arg(i)` | `arg(i) -> string` | i-й аргумент командной строки; `""` если индекс вне диапазона |
| `read(fn)` | `read(fn: string) -> string` | Весь файл в виде строки; `""` если файл не читается |
| `write(fn, s)` | `write(fn: string, s: string) -> bool` | Записать `s` в `fn` с усечением; `true` при успехе |
| `input()` | `input() -> string` | Одна строка из стандартного ввода без завершающего перевода строки; `""` в конце файла |

## 13. Регион `hot`

Блок `hot` помечает участок как критический горячий путь. Это обычный блок области видимости (внутри работают переменные, операторы и циклы), и компилятор применяет кэш-ориентированные оптимизации ко всему, что он покрывает:

- охватывающая функция получает в LLVM атрибут `hot` (агрессивное встраивание, развёртывание циклов, векторизация);
- каждая обратная дуга цикла внутри блока несёт метаданные `llvm.loop`, включающие векторизацию (ширина 4) и развёртывание (счётчик 4);
- локальные слоты выравниваются по кэш-линии (64 байта);
- выделения в арене, сделанные в линейном коде внутри блока (конкатенация, литералы, `new`), предварительно подгружаются в L1 до первого использования.

Тела циклов намеренно не получают программную предвыборку: любой вызов внутри цикла заставляет векторизатор LLVM отклонить этот цикл, а векторизованный цикл проходит через L1 намного быстрее, чем могла бы помочь подсказка о предвыборке, — последовательный доступ и так покрывается аппаратным префетчером.

Конвейер сборки запускает `opt -O2` между генерацией кода и `llc` — именно этот этап использует атрибут `hot` и метаданные `llvm.loop`; без этого этапа подсказки никогда не дошли бы до оптимизатора.

Блоки `epoch` внутри `hot` запрещены: откат арены удалил бы те самые строки кэша, которые регион закрепляет, поэтому семантический анализатор сообщает `epoch inside hot region defeats L1 cache pinning`.

```aev
hot {
    let total = 0;
    for (let i = 0; i < len(data); i += 1) {
        total = total + data[i];
    }
    print total;
}
```

## 14. Стандартная библиотека

Стандартная библиотека поставляется вместе с компилятором, по возможности написана на Aevix и обходит `aevix.lock`:

```aev
import "std:";          // все модули, плоско в текущую программу
import "std:text";      // только один модуль
```

| Модуль | Содержимое |
| :--- | :--- |
| `std:text` | `is_empty`, `repeat`, `pad_left`, `pad_right`, `index_of`, `last_index_of`, `count`, `strip_prefix`, `strip_suffix`, `equals_ignore_case` |
| `std:io` | `read_file`, `write_file`, `read_line`, `read_all`, `print_line`, `print_lines` |
| `std:math` | `clamp`, `pow_int`, `fact`, `gcd`, `lcm`, `is_even`, `is_odd`, `pi`, `e` (плавающие `sqrt`/`sin`/`cos`/`tan`/`log`/`exp`/`floor`/`ceil`/`pow` — встроенные) |
| `std:collections` | помощники для срезов и мономорфные хеш-таблицы map/set |

### Коллекции

`std:collections` предоставляет функции для срезов на месте (`sort_int`,
`reverse_int`, `index_of_int`, `contains_int`, `min_int`, `max_int`,
`sum_int`) и четыре хеш-контейнера на арене:

```aev
import "std:collections";

let m = new_map_str_int();
map_str_int_put(m, "hits", 7);
map_str_int_put(m, "misses", 2);
print(map_str_int_get(m, "hits"));     // 7
print(map_str_int_has(m, "misses"));   // true
map_str_int_remove(m, "misses");

let s = new_set_int();
set_int_add(s, 1);
set_int_add(s, 2);
set_int_add(s, 1);
print(set_int_size(s));                // 2
print(set_int_contains(s, 2));         // true
```

| Тип | Конструктор | Операции |
| :--- | :--- | :--- |
| `MapIntInt` | `new_map_int_int()` | `map_int_int_put/get/has/remove`, `keys`, `values`, `size`, `clear` |
| `MapStrInt` | `new_map_str_int()` | `map_str_int_put/get/has/remove`, `keys`, `values`, `size`, `clear` |
| `SetInt` | `new_set_int()` | `set_int_add/contains/remove`, `items`, `to_array`, `size`, `clear` |
| `SetStr` | `new_set_str()` | `set_str_add/contains/remove`, `items`, `to_array`, `size`, `clear` |

Ключи хешируются методом открытой адресации, таблица растёт после 70% заполнения; для строковых ключей используется `str_hash`. Контейнеры **мономорфны** — дженериков в языке пока нет, поэтому варианты для `int` и `string` предоставляются явно. `free` не нужен: память живёт в арене и освобождается при откате эпохи.
