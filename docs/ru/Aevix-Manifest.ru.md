# МАНИФЕСТ ЯЗЫКА AEVIX (v0.3.9)

> **Видение:** Преодолеть разрыв между высокой продуктивностью разработчиков и низкоуровневым контролем над железом, обеспечивая детерминированное, экстремально производительное программное обеспечение без когнитивных затрат на ручные доказательства безопасности памяти.

---

## 🎯 Основные цели

Главная задача Aevix — обеспечить **скорость уровня C/ASM** и **абсолютную безопасность**, сохраняя удобство разработки, которое позволяет избежать «борьбы с механизмом проверки заимствований», характерной для современных системных языков.

## 🚀 Основные принципы (ключевые возможности)

### 1. Самооптимизирующаяся семантика (SOS)

**Концепция:** компилятор рассматривает исходный код как отправную точку, а не как окончательную инструкцию. Он выполняет глубокий статический анализ и переписывает логику на лету.

- **Механизм:** автоматическое преобразование умных указателей (Arc/Rc) в переменные, размещённые на стеке, когда анализ выхода за пределы области доказывает безопасность. Сложные циклы автоматически преобразуются в SIMD-конвейеры.
- **Эффект:** высокоуровневые абстракции с нулевой стоимостью выполнения.

### 2. Атомарная память (горячий путь, независимый от кэша)

**Концепция:** устранение недетерминированных задержек за счёт контроля над иерархией памяти.

- **Механизм:** ключевое слово `hot` для региона явно ограничивает доступ к данным кэшем L1 или регистрами, обходя изменчивость L2/L3.
- **Эффект:** гарантированное детерминированное время выполнения (нулевое дрожание задержек). Критично для высокочастотной торговли (HFT), DSP реального времени и физических движков.

### 3. Многотемпоральная модель памяти (эпохи)

**Концепция:** замена сложных времён жизни временной системой «эпох».

- **Механизм:** память выделяется в «эпохах» (например, на кадр в игровом движке). В конце эпохи вся арена освобождается мгновенно.
- **Эффект:** решает проблему «циклических ссылок» без сборщика мусора. Линейный доступ к памяти с нулевыми затратами на управление.

### 4. Контекстуальный полиморфизм (перегрузка по контексту)

**Концепция:** машинный код, адаптирующийся к своему окружению.

- **Механизм:** компилятор генерирует различные двоичные реализации одной и той же функции в зависимости от места вызова (например, встраивание для циклов, добавление атомарных барьеров для многопоточности).
- **Эффект:** единый источник истины, но идеально подогнанный машинный код для каждого сценария.

### 5. Декларативная безопасность (доказуемая безопасность)

**Концепция:** перенос безопасности с «проверок во время выполнения» на «доказательства во время компиляции».

- **Механизм:** разработчики задают инварианты как логические условия. Компилятор математически доказывает, что эти условия всегда истинны, что позволяет безопасно убрать проверки границ и проверки нулевого указателя.
- **Эффект:** безопасность уровня формальной верификации без необходимости писать внешние скрипты доказательств.

## 🛠 Техническая основа

- **Бэкенд:** LLVM / MLIR для продвинутых преобразований SOS.
- **Парадигма:** синтез проектирования, ориентированного на данные (DOD), и контекстуального полиморфизма.
- **Система типов:** зависимые типы для проверки инвариантов.
- **Управление памятью:** арены на основе эпох и линейные аллокаторы.

## Текущий статус (v0.3.9)

**Реализовано:** статическая система типов (int, float, bool, string, типы фиксированной ширины, структуры, перечисления), арены на основе эпох с анализом выхода за пределы области, параметры по ссылке, массивы и срезы, встроенные строковые функции и `str_hash`, f-строки, `%`, `match`, горячие регионы, многофайловые импорты с пространствами имён, поставляемая стандартная библиотека (`std:text`, `std:io`, `std:math`, `std:collections` с хеш-таблицами map/set) и менеджер пакетов с зависимостями по путям и git.

**В процессе:** центральный реестр пакетов, дженерики языка, полный анализ выхода за пределы области для параметров.

**Планы:** преобразования SOS, контекстуальный полиморфизм, доказуемая безопасность.
