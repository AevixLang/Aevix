# Журнал изменений Aevix

Все заметные изменения документированы здесь. Формат следует принципам [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), проект использует [семантическое версионирование](https://semver.org/spec/v2.0.0.html).

## [Не выпущено]

## [0.3.8] — 2026-10-26

### Добавлено

- **Русская локализация документации** — полные русскоязычные аналоги официальной документации в `docs/ru/` (`README.ru.md`, `Syntax.ru.md`, `Aevix-Architecture.ru.md`, `Aevix-Manifest.ru.md`, `CONTRIBUTING.ru.md`, `CHANGELOG.ru.md`). В главном `README.md` наверху сохранён переключатель языков.

## [0.3.7] — 2026-10-26

### Добавлено

- **Укрепление режима `vendor` в aevix-pm** — команда `vendor` теперь переписывает `aevix.lock` на скопированное дерево `lib/vendor/<name>`, поэтому проект с внедрёнными зависимостями собирается и работает полностью без сети, даже если исходники зависимости исчезли. `copyTree` также пропускает метаданные `.git` и отказывается от символических ссылок.

## [0.3.6] — 2026-10-26

### Добавлено

- **aevix-pm (этап P1)** — `update [name]` разрешает каждую зависимость по пути к новейшей git-метке, удовлетворяющей объявленному диапазону семантического версионирования; `tree` и `why` теперь обходят транзитивные связи зависимостей из вложенных манифестов. Решатель semver (`PickNewest` и псевдонимы) доступен для вызова.

## [0.3.5] — 2026-10-26

### Добавлено

- **Карты и множества на основе арены** — `std:collections` получает мономорфные `MapIntInt`, `MapStrInt`, `SetInt`, `SetStr` (структуры с `new`, `put`/`get`/`has`/`remove`, `add`/`contains`, вспомогательными функциями роста, `keys`/`values`/`items`). Линейный поиск по непрерывным массивам в арене; оба фронтенда обрабатывают внедрённые структуры без изменений.

## [0.3.4] — 2026-10-26

### Добавлено

- **Запрет вложенных функций задокументирован** — вложенные объявления `func` навсегда отклоняются; `Syntax.md` теперь явно формулирует правило, а два теста-фикстуры закрепляют диагностическое сообщение.

## [0.3.3] — 2026-10-26

### Добавлено

- **Выражение match** — `match (x) { case 1 => 10, case 2 => 20, default => 30 }` возвращает значение типа веток. Все ветки должны согласовываться по типу; `default` обязателен, если исследуемое значение не является перечислением, и может быть опущен для полного покрытия перечисления; дублирующиеся варианты перечисления отклоняются. Поддерживаются числовые, вещественные, строковые значения и перечисления. Реализовано в обоих фронтендах и понижается до узла `MatchExpr` (новая схема AST v6).

## [0.3.2] — 2026-10-25

### Добавлено

- **Псевдонимы импортов / пространства имён** — `import "mod.aev" as mod;` помещает объявления модуля за псевдоним: `mod.fn(...)`, типы `mod.Point`, литералы `mod.Point { ... }` и доступ к вариантам перечислений `mod.Color.variant`. Модули, экспортирующие одинаковые имена, теперь могут сосуществовать; каждый внутренне переименовывается в `alias__name`, его ссылки переписываются, а затем полные ссылки импортирующего файла разрешаются в эти имена. Плоские импорты по-прежнему объединяются как раньше. Оба фронтенда реализуют одно и то же правило.
- **Пример из трёх пакетов** — `examples/packages/` собирает три локальных пакета, каждый экспортирует `Entity` под отдельным псевдонимом.

### Документация

- `Syntax.md` описывает доступ через псевдоним; `README.md` больше не указывает пространства имён как ограничение.

## [0.3.1] — 2026-10-24

### Добавлено

- **`std:collections`** — `sort_int` (на месте), `reverse_int`, `index_of_int`, `contains_int`, `min_int`, `max_int`, `sum_int`.
- **Диапазоны семантического версионирования в `aevix-pm`** — `add --version` проверяет `^`, `~`, `=`, `>=`, `<=`, `<`, `>` и диапазоны, разделённые запятыми.

### Исправлено

- **Сокращённое вычисление `&&` / `||`** — phi-узел результата записывал неверный предшествующий блок, поэтому операнд, вычисляемый во вложенном блоке (например, `while (j >= 0 && arr[j] > v)`), читал неопределённое значение. Issue #12.
- **`assert()`** — принимает условия типа `bool` в дополнение к целым числам.

## [0.3.0] — 2026-10-24

### Добавлено

- **Стандартная библиотека (`std:`)** — `std:text`, `std:io`, `std:math` поставляются *вместе* с инструментарием и обходят `aevix.lock`. `import "std:"` загружает полный набор; отдельные модули доступны как `std:text` и т.д.
- **Оператор остатка `%`** — полная поддержка (грамматика, оба фронтенда, семантика, генерация кода).
- **Оператор `match`** — `match (x) { case V: { ... } default: { ... } }`, понижается до цепочки `if`; перечисления требуют полного покрытия или `default` (проверяется семантикой), дублирующиеся ветки отклоняются.
- **Встроенные математические функции для float** — `sqrt`, `sin`, `cos`, `tan`, `log`, `exp`, `floor`, `ceil`, `pow` (внутренние функции LLVM поверх среды выполнения).

### Изменено

- **Строковые предикаты возвращают `bool`** — `contains`, `startswith`, `endswith` теперь типизированы как `bool` (документация уже так утверждала); генерация кода усекает `i32` среды выполнения до `i1`.

## [0.2.0] — 2026-10-13

Релиз, посвящённый укреплению и безопасности памяти. Статические проверки переезжают в выделенный этап семантики, который становится единственным источником истины, а горячие регионы получают настоящие оптимизации для кэша L1.

### Добавлено

- **Выделенный этап семантики** — проверка типов, областей видимости и выхода за пределы эпохи вынесена из генерации кода в отдельный этап конвейера (`aevix build --stage sema`).
- **Оптимизации горячих регионов для кэша L1** — атрибут `hot` в LLVM, метаданные векторизации и развёртывания циклов, локальные переменные с выравниванием по кэш-линии (64 байта), предвыборка выделений памяти в линейном коде и новый этап конвейера `opt -O2`, который использует эти метаданные. `epoch` внутри `hot` запрещён.
- **Типы фиксированной ширины** — `i8`–`i64`, `u8`–`u64`, `f32`/`f64` с кодогенерацией, учитывающей ширину, и принудительными правилами преобразования.
- **Перечисления** — именованные целочисленные константы, индексы в порядке объявления, печать имён.
- **Именованные литералы структур** — `Point { y: 2, x: 1 }`, любой порядок, «либо всё, либо ничего» (позиционный и именованный стили нельзя смешивать). *Поднимает схему AST с v4 до v5.*
- **Встроенные строковые функции** — `trim`, `contains`, `replace`, `upper`, `lower`, `startswith`, `endswith`, `char_at`, а также посимвольная индексация строк.
- **`rand(max)`** и **`assert(cond)`**.
- **Фронтенд на C++** — лексер, парсер и средство разрешения импортов переписаны на C++ (примерно в 20 раз быстрее); фронтенд на Python остаётся запасным вариантом.
- **Диагностика с реальными позициями** — `line`/`col` из фронтенда на C++ и настоящее имя исходного файла доходят до консольной утилиты (ранее каждая ошибка показывала `input.aev` без позиции).
- **Эталонный набор вывода и `aevix bench`**, временные каталоги сборки для каждого исходника, замер времени этапов и флаг `--stage` для запуска отдельного этапа конвейера.

### Изменено

- **Проверки выхода за пределы выполняются в семантике, а не в генерации кода** — семантика теперь моделирует происхождение строк (литерал = глобальная константа, результат конкатенации или встроенной функции = память арены), поэтому выходы за пределы эпохи обнаруживаются на один этап раньше.
- **Параметры `ref` передаются по адресу** с правилами lvalue, инициализации и псевдонимов; ключевое слово `out` убрано — единственный `ref` покрывает вход и выход.
- **Глобальные `let` опираются на глобальные переменные модуля**, поэтому тела функций могут присваивать переменные уровня файла (ранее это была ошибка генерации кода).
- **`aevix test` переименован в `aevix selftest`** с форматированным средством запуска тестов.

### Исправлено

- **Использование после освобождения через срезы, обёрнутые в структуры** — срез арены, вложенный в структуру, больше не может выйти за пределы своей эпохи (правило `no-uaf` восстановлено).
- **Выход за пределы эпохи через значения структур** — переменные структур, литералы структур и результаты вызовов, возвращающие память арены, отклоняются семантикой.
- **Литералы массивов структур** компилируются в аннотированной форме открытого массива (`let a: P[] = [P { 1, 2 }];`).
- **Печать открытого массива структур** больше не завершается ошибкой при генерации кода.
- **Вложенные объявления `func`** отклоняются семантикой с понятным сообщением (функции допустимы только на верхнем уровне).
- **Отсутствующий исходный файл** выдаёт понятную ошибку утилиты вместо падения.

## [0.1.0] — 2026-09-30

Первый работающий сквозной конвейер: исходный код → нативный двоичный файл через LLVM.

### Добавлено

- **Система типов** — `int`, `float`, `bool`, `string`, структуры.
- **Память на аренах на основе эпох** — откат за O(1), анализ выхода за пределы области, без сборщика мусора.
- **Массивы и срезы** — фиксированного размера (по значению) и открытые (выделяемые в арене) с `new` и проверкой границ во время выполнения.
- **Параметры по ссылке** (базовые).
- **Многофайловый `import`** с обнаружением циклов.
- **Маркер области `hot`** (только атрибут; оптимизаций для кэша L1 пока нет).
- **Консольная утилита на Go** — оркестрация `build`, `run`, `selftest`, `bench`, `clean`.
- **Бэкенд LLVM** — генерация IR, `llc`, `clang` и компоновка со средой выполнения.
